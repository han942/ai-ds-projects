# LLM 리뷰 속성 추출 overview

질문: 리뷰에서 추출한 표현이 같은 사용자가 준 평점의 순서를 따르는가?

**현재 판단: 평점과 연결되는 신호는 확인했다. 추출 보완과 미래 추천 성능 검증이 필요하다.**

| 표현 | 점수가 있는 리뷰 | 사용자 평균 Spearman | 리뷰 쌍 순서 일치 | 95% 구간 |
|---|---:|---:|---:|---|
| 언급 속성 5개 평균: 재방문 제외 | 2,089 | 0.507 | 74.2% | 71.1~77.4% |
| 전체 만족 표현 | 2,012 | 0.538 | 74.8% | 71.5~77.8% |

2026-10-06, snapshot `e7896add5b4b5939`의 이력 수 상위 15명·텍스트 리뷰 2,139개를 OpenRouter 무료 Nemotron 3 Super로 분석했다. 낮은 평점도 포함했다. 실제 평점·사용자·식당의 별도 필드는 추출 모델에 보내지 않았다. 맛·가성비·서비스·분위기·양·재방문 의향과 원문 근거를 추출했으며 임베딩을 생성한 실험은 아니다.

쌍 일치는 같은 사용자 내 실제 평점이 다른 리뷰를 비교하고 감정 동점은 0.5점으로 계산한 사용자 평균이다. **74.2%는 미래 식당 추천 정확도가 아니다.** 같은 리뷰와 평점의 사후 진단이며 고활동 15명에 대한 결과다. 전체 만족과 속성 평균의 같은 리뷰 비교 차이 구간도 0을 포함해 어느 쪽이 더 낫다고 확정하지 않는다.

원문과 다른 인용을 가진 의견 229개는 unknown으로 제외했다. 대기 불만 누락·재방문 과잉 추론은 남았다. Codex의 별도 30개 표본 검토는 사람 정답 라벨 검증이 아니다. 위 표는 기존 v3 실행 결과이며 아래 v4 보완의 성능을 뜻하지 않는다.

사용 가능한 API 응답 45개, 기록 비용 $0. 입출력·인용·개인별 지표를 독립 검증했고 관련 테스트 8개가 통과했다. 추출 결과·벡터 CSV·API 응답은 `review_aspects.zip`, 상세 리포트와 사용자별 원문 근거는 `detailed_reports.zip`에 보관했다. 원본 run은 `20261006_top15_nemotron3_v3`이다. [보관·복원 안내](../artifacts/README.md).

## 근거 추출 v4 보완

인용문을 생성하는 대신 같은 리뷰의 `sentence_id` 1~2개를 선택한다. 코드는 선택한 원문 전체를 복원하고 번호와 문자 위치를 보존한다. 문장 분할은 줄바꿈·문장부호에 따른 결정적 구간 분할이며 언어학적 문장 분석은 아니다. 별점 마스킹은 독립 구간으로 분리해 인접한 의견을 버리지 않는다. 긴 문장의 부정어·대조 표현도 자르지 않고 남긴다.

- 없는 번호·중복 번호·정수가 아닌 번호·별점 마스킹이 포함된 근거는 unknown으로 제외한다. 원본 응답과 제외 이유를 남긴다. 위치는 별점 표현을 마스킹한 `extraction_text`의 Python 문자 인덱스이며 `[start, end)`다.
- 대기·웨이팅 불만을 서비스에서 확인하고 재방문은 명시적 의향으로만 판단하도록 프롬프트를 보완했다. 의미 해석의 정확성은 원문 위치 검증과 별도로 검토해야 한다.
- v3 캐시는 `--analyze-only`로 재분석할 수 있다. v4는 새 출력 폴더에서 실행해 기존 결과와 섞지 않는다. API에는 review_id와 번호가 붙은 원문만 전달하며 별도 평점·사용자·식당 필드는 보내지 않는다.

프로젝트 루트에서 입력만 준비하려면 아래 명령을 쓴다. API를 호출하지 않는다. `--prepare-only`를 빼면 새 방식으로 추출하며, 실행을 마친 뒤 `--analyze-only`로 캐시를 재분석할 수 있다.

```bash
python -m rating_recsys.experiments.review_aspect_audit \
  --output artifacts/review_aspects/20261006_top15_sentence_v4 \
  --users 15 --batch-size 20 --concurrency 2 --prepare-only
```

관련 테스트 27개가 통과했다. 실제 2,139개 리뷰의 입력을 준비하고 원문 구간 7,522개의 위치·텍스트 보존·입력 hash를 검증했다. 별점 마스킹 구간 23개를 제외해도 모든 리뷰에 선택 가능한 근거 구간이 남았다. 검증 기록은 위 출력 폴더의 `input_validation.json`에 있다. API 호출은 없었다.

v4 코드 보완과 입력 준비는 추천 성능이나 추출 품질 향상의 검증이 아니다. 새 추출 실행·표본 검토·동일 리뷰에서의 v3/v4 비교는 아직 수행하지 않았다. 구체적인 음식·맛 의견을 여러 개 보존하는 구조와 추천 모델 결합은 후속 작업이다.
