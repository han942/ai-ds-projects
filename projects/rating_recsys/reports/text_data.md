# 리뷰 텍스트 데이터: 특징과 조사 기준

**조사 목적**

- 수집 리뷰의 정보 범위 확인
- 검색·재정렬·개인화에 필요한 입력 조건 확인

문서 정리: 2026-10-13. DB·CSV 측정: 2026-10-10; 이번에는 다시 조회하지 않았다.

**전체 DB 96,922건의 기초 조사를 완료했다.** 다음 세 특징은 입력 설계를 점검할 근거이며, 텍스트 모델의 성능 원인을 입증한 결과는 아니다.

이 조사의 목적은 데이터가 얼마나 큰지보다 **사용자에게 어떤 취향 근거가 실제로 있는지**를 파악하는 것이다. DB 전체에 리뷰가 많아도 한 사용자에게는 몇 개만 있을 수 있고, 높은 별점 안에도 가격·대기·서비스에 대한 불만이 섞일 수 있다. 입력을 고르거나 평균하기 전에 이 차이를 확인해야 한다.

1. 짧은 리뷰

   - 본문 길이 중앙값: 61자
   - 100자 이하: 71.90%
   - 우선 확인: 긴 chunk보다 관련 과거 리뷰를 고르는 방식

2. 사용자별 근거 부족과 불균형

   - 사용자별 본문 중앙값: 2개
   - 리뷰 1~4개 사용자: 68.65%
   - 우선 확인: 이력 구간별 실제 입력량과 본문 없는 사용자 처리

3. 높은 평점 집중

   - 4점 이상: 86.57%
   - 우선 확인: 높은 별점 안의 불만·대조 표현과 개인별 평점 습관

의미 주석과 기존 모델의 전체 임베딩 분포 조사는 미실행이다. 조사 수치의 분모·측정 범위와 후속 과제를 아래에 구분한다.

## 데이터 단위

DB의 한 행이 그대로 모델 입력 한 개가 되는 것은 아니다. 재방문을 포함한 수집 자료에서 첫 상호작용을 고르고, 추천 시점 이전 이력만 남긴 뒤 길이 제한과 집계를 적용한다. 아래 단위를 구분해야 원문에 있었던 정보와 실제 모델이 받은 정보를 혼동하지 않는다.

| 단위 | 정의 | 구분하는 이유 |
|---|---|---|
| 수집 행 | CSV 또는 DB의 리뷰 기록 | 재수집·수집 실패·원문 보존 점검 |
| 고유 리뷰 | Ingestion의 `content_hash` 기준 중복 제거 | 내용 중복 기준이며 실제 방문의 유일성 보장은 아님 |
| 모델 interaction | 사용자–식당별 첫 방문 기록 | 전체 리뷰와 추천 학습 모집단 구분 |
| Cutoff별 이력 | 추천 시점 이전 방문·리뷰 | 미래 정보가 입력에 섞이는 누수 방지 |
| 모델 입력 | 선택·정규화·분할·토큰 제한·집계 후 자료 | 모델에 실제로 남는 정보 확인 |
| 검색 근거 | 특정 사용자·후보를 위해 선택한 리뷰·문장 | 근거의 관련성과 식당 추천 정확도를 따로 평가 |

원문 통계와 실제 입력의 보존율은 다르다. 리뷰·사용자·식당별 집계도 구분해야 고활동 집단에 결과가 치우치는 것을 확인할 수 있다.

### 사용자 이력의 불균형

### 우선 추천 가설

2026-10-10 조사에서 나온 가설과 이후 실험 상태를 구분한다. 현재 후속 범위는 전체 catalog에서 후보를 찾는 retrieval이다.

| 가설 | 근거·상태 |
|---|---|
| 이력이 짧은 사용자의 텍스트 보조 | 사용자·식당 정보량 비대칭. 이력 구간별 효과와 실제 본문량을 분리해 검증해야 함 |
| 평점과 속성 의견 분리 | 높은 별점 안의 불만·대조 표현을 층화 주석. 이 프로파일의 원문 의미 주석은 미실행 |
| 평균 대신 리뷰별 matching | 관련 리뷰·속성·상황을 보존하는 가설. 이후 mean/late·shuffle retrieval 비교는 [리뷰 임베딩 리포트](./review_embeddings.md)에 있으며 텍스트 효과를 확인하지 못함 |
| 과거 추가 리뷰 활용 | Cutoff 이전 전체 78,164건−첫 상호작용 70,883건=추가 7,281건. 신규 정보인지 확인 후 첫 방문 label과 text sidecar를 분리하는 조건은 미실행. 추가 기록을 재방문으로 자동 판정하지 않음 |

전체 DB 통계에는 holdout 이후 리뷰도 포함된다. 이 조사로 모델 성능 병목이나 개선 원인을 확정하거나 새 모델을 선택하지 않는다.

## 재현과 근거

프로젝트 루트에서 실행한다. Supabase 스크립트는 기존 `.env` 설정과 psycopg를 사용해 읽기 전용 조회한다. 연결 정보와 개인별 원문은 결과에 기록하지 않는다. CSV 스크립트는 DB에 연결하지 않는다.

```bash
.venv/bin/python scripts/profile_supabase_texts.py --train-cutoff 2025-12-19
```

- [Supabase 조회 SQL](../queries/profile_supabase_text.sql), [DB 프로파일 코드](../scripts/profile_supabase_texts.py).
- 과거 독립 SQL 재검산 `artifacts/text_data/supabase_verification.json`: 리뷰/본문/평점/고유 사용자–식당 수와 길이 분위수가 전체 조회 Python 집계와 일치.
- 과거 DB 집계 `artifacts/text_data/supabase_profile.json`: 조회 시각·격리 수준·schema·SQL·구현 SHA-256·cohort·집계·한계.
- 과거 DB 조사 노트북 `artifacts/text_data/supabase_profile.ipynb`: 저장 집계의 분모·해석·검증; DB 자동 재조회 없음.

로컬 CSV 비교를 재현하려면 다음을 실행한다.

```bash
python scripts/profile_review_texts.py
```

- 과거 집계 `artifacts/text_data/local_csv_profile.json`: 파일 SHA-256·수집일·제외 이유·지표 정의·한계·평점/지역 집계.
- 과거 재실행 노트북 `artifacts/text_data/local_csv_profile.ipynb`: 분석 코드·출력·해석.
- [ingestion 정규화·키·날짜](../src/rating_recsys/ingestion/transform.py), [모델 첫 방문 선택](../src/rating_recsys/datasets/repository.py), [snapshot과 리뷰 sidecar](../src/rating_recsys/experiments/snapshot.py).

노트북은 당시 코드 셀을 순서대로 실행해 출력을 저장했으며 Jupyter UI 렌더는 미확인이다. 위 JSON·노트북은 Git 제외 로컬 artifact로, **2026-10-13 문서 정리 시 현재 작업 폴더의 `artifacts/text_data/`에는 없었다.** 수치는 기존 측정 기록을 보존한 것이며 이번 작업에서 원본 집계를 재검산하지 못했다.

CSV 파일명은 수집 시각이며 작성 시각과 다르다. 당시 조사에서도 test 정답·성능을 계산하거나 모델 선택에 사용하지 않았다. [RAG·multi-stage 검색 방법론 연결](./bm25.md#rag와-multi-stage-추천에서-공유할-방법론)은 별도 문서를 따른다.
