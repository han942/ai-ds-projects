# 리뷰 텍스트 데이터: 특징과 조사 기준

질문: 수집한 리뷰에는 어떤 정보가 있고, 그 정보를 검색·재정렬·개인화에 사용하려면 무엇을 먼저 확인해야 하는가?

**현재 판단: Supabase 전체 96,922건을 조사했다. 짧은 리뷰가 많고, 사용자별 정보량이 적으며, 높은 평점에 집중되어 있다.** 먼저 사용자별 과거 근거를 얼마나 확보할 수 있는지, 높은 별점 안에서도 속성별 불만을 보존하는지 확인한다. 의미 주석과 기존 모델의 전체 임베딩 분포 조사는 미실행이다.

후속 [RQ-VAE 실험](./rqvae.md)에서는 새 리뷰별 E5 입력의 토큰 길이와 압축 후 표현 보존을 측정했다. 과거 고유 본문 68,777종의 접두어 포함 토큰 길이는 P50/P90/P95/P99가 39/121/184/289이며, 512토큰 초과는 71종 (0.10%)이다. 이 수치는 해당 tokenizer·전체 본문 passage 입력 기준이며 기존 RLMRec 문장 블록이나 모든 모델의 절단률로 일반화하지 않는다.

검색 후 재정렬하는 RAG와 multi-stage 추천에서 가져올 아이디어는 [검색 방법론 연결](./bm25.md#rag와-multi-stage-추천에서-공유할-방법론)에 기록했다. 이 문서는 데이터 특징·측정 이유·후속 조사 기준을 유지한다.

## 먼저 나눠야 할 데이터 단위

| 단위 | 정의 | 구분하는 이유 |
|---|---|---|
| 수집 행 | 수집 CSV 또는 DB에 들어온 리뷰 기록 | 재수집·수집 실패·원문 보존을 확인한다 |
| 고유 리뷰 | ingestion의 `content_hash` 기준으로 중복을 제거한 기록 | 같은 자료를 여러 번 세는 문제를 줄인다. 실제 방문의 유일성을 보장하는 키는 아니다 |
| 모델 interaction | DB에서 사용자–식당별 첫 방문을 선택한 기록 | 전체 리뷰와 현재 추천 학습 모집단은 다르다 |
| cutoff별 이력 | 추천 시점 이전에 이용 가능한 방문·리뷰 | 미래 리뷰·평점으로 추천하는 누수를 막는다 |
| 모델 입력 | 이력 선택·정규화·문장/블록 분할·토큰 제한·프로필 집계를 적용한 자료 | 원문에 있던 정보가 실제 입력에 얼마나 남는지 확인한다 |
| 검색 근거 | 특정 사용자·후보에 대해 선택한 리뷰 또는 문장 | 관련 근거 검색과 식당 추천 정확도를 별도로 평가한다 |

원문 조사와 모델 입력 조사를 같은 수치로 표현하지 않는다. 리뷰 단위, 사용자 단위, 식당 단위의 평균도 구분한다. 글이 많은 사용자·식당이 전체 평균을 지배할 수 있다.

## Supabase DB 전체 조사

2026-10-10 **15:05 KST**에 실제 PostgreSQL `recsys` 스키마를 조회했다. **전체 DB → 사용자–식당 첫 상호작용 → 기존 학습 cutoff**를 같은 `REPEATABLE READ / READ ONLY` 트랜잭션에서 조사했다. 전체 리뷰를 읽었으며 표본 추정이 아니다. 개인 이름·ID·원문은 결과 파일에 저장하지 않았다.

| 모집단 | 리뷰/상호작용 수 | 본문 있음 | 사용자 수 | 식당 수 | 본문 길이 중앙값 / P90 |
|---|---:|---:|---:|---:|---:|
| DB 전체 리뷰 | 96,922 | 94,301 (97.30%) | 14,008 | 4,587 | 61 / 220자 |
| 사용자–식당 첫 상호작용 | 88,554 | 86,271 (97.42%) | 14,008 | 4,587 | 61 / 213자 |
| 첫 상호작용 중 event_date ≤ 2025-12-19 | 70,883 | 69,359 (97.85%) | 11,655 | 4,404 | 59 / 197자 |

첫 상호작용은 현재 `InteractionRepository`와 같은 규칙으로 선택했다. 전체 interaction digest는 `e7896add5b4b593981fc169ded53eb149e98784697b6b82313d4ef06aa99c72a`로 기존 실험 snapshot과 일치한다. 이 digest는 **interaction 필드**의 동일성을 확인하며, 기존 review sidecar·E5 캐시의 본문 hash까지 검증한 것은 아니다. 마지막 행에는 최소 이력·추천 정답 조건을 추가하지 않았다.

학습 cutoff cohort에서 본문 있는 사용자 10,961명·식당 4,403곳은 기존 RLMRec 프로필 coverage와 일치한다. 전체 DB의 905명과 달리 이 cohort에서는 694명에게 본문이 없다. 모델 입력 논의에는 전체 DB 평균과 함께 해당 cutoff의 분포를 사용한다.

### 사용자 이력의 불균형

사용자별 본문 수 중앙값은 **2개**, P90은 18개이고 식당별 중앙값은 **13개**, P90은 43개다. 첫 상호작용의 학습 cutoff cohort에서는 사용자별 중앙값 2개·P90 16개, 식당별 중앙값 10개·P90 35개다. 이 cohort에서도 첫 interaction 4개 이하 사용자는 8,214/11,655명 (70.48%)이고 첫 interaction 10개 이상 사용자 1,953명의 interaction은 47,680/70,883개 (67.27%)다. 본문 없는 엔티티를 0개로 포함한다.

정규식 어휘 단서로 탐색했다. 분모는 본문 94,301개이며 한 리뷰에 여러 단서가 있을 수 있다. 아래 결과는 의미 주석·주제 분류·작성자의 선호 판정이 아니다.

맛 단서에는 일반적인 `맛있다`도 들어간다. 맛 언급이 많다는 사실은 차별적인 취향 정보가 많다는 뜻이 아니다. 취향 어휘가 없는 리뷰에도 선호가 표현될 수 있고, `아이` 등 상황 단서는 다른 단어에 포함되거나 작성자 외 사람을 가리킬 수 있다. 개인 선호와 일반 품질 평가를 구분하는 층화 원문 검토가 필요하다.

### 수집 출처·날짜·무결성

전체 리뷰는 기존 5개 출처의 DB 기록 **23,207건**과 2026-09 전국 Playwright 수집 **73,715건**으로 구성된다. 앞선 CSV 결과는 전자의 규모와 같으며 DB 전체를 대표하는 통계는 아니었다. SQL의 region은 DB에 저장된 분류로, 서울 38,498·경기 17,946·부산 15,649·인천 9,123·대구 8,392·광주 4,378·전국 2,936건이다. `전국` 값은 실제 주소의 지역을 다시 판정한 결과가 아니다.

| 확인 | 결과와 의미 |
|---|---|
| ID·content hash·join | review ID와 content hash 각각 96,922개 고유. 사용자·식당·crawl run orphan 0건, join 후 96,922건 유지. 원천 동명이인·식당 엔티티 병합은 별도 미검증 |
| 평점·날짜 precision 도메인 | 허용 범위/precision 이탈 0건. 리뷰 날짜 누락 3건은 기존 interaction 로직에 따라 KST 수집일로 대체 |
| 작성일 precision | exact 78,425 (80.92%), 연도 추론 18,005 (18.58%), 상대 날짜 489, unknown 3건. 학습 cutoff cohort는 exact 70,434/70,883건 (99.37%) |
| 날짜 범위 | 파싱된 작성일 2016-04-19~2026-09-26, 수집 시각 2025-09-05~2026-09-26. 파싱된 작성일이 수집일 이후인 기록 0건 |
| DB 적재 시각 | 2026-09-19~2026-09-26 KST. event_date ≤ 2025-12-19 필터는 뒤늦게 수집한 과거 경험을 재구성한다. 당시 DB에 텍스트가 존재했다는 뜻이 아니다 |
| crawler 본문 완결 flag | 전국 수집에서 true 73,702·false 13건, 기존 23,207건은 flag 없음. collector 선언으로 실제 의미 완결성을 독립 검증한 것은 아니다 |
| payload 본문 연결 | 모든 96,922건에 `user_query` 필드 값이 있으며 같은 규칙으로 정규화한 결과가 저장 본문과 일치한다. 이 필드는 수집기에서 이미 변환했을 수 있어 웹 DOM 원문을 의미하지 않는다 |
| 줄바꿈 출처 차이 | 본문 있는 기록의 payload `user_query` 중 줄바꿈 있는 14,267개는 모두 기존 출처다. 전국 수집은 0개. 수집기/출처 차이와 실제 문체 변화를 구분하지 못했으므로 전체 리뷰의 문장 구조 차이로 해석하지 않는다 |
| 재정규화 | DB 저장 본문을 같은 ingestion 규칙으로 재정규화해 달라진 기록 0개. 수집 당시 DOM→payload→본문의 정보 손실이 0이라는 뜻은 아니다 |

분기별·지역별·평점별·출처별 길이/coverage/어휘 집계는 JSON에 남겼다. 하나의 수집 snapshot에서 시간 구간 차이는 생존·수집·사용자 구성의 차이도 섞이므로 취향 변화나 수집 품질 개선을 확정하지 않는다.

### 이 데이터에서 우선 검토할 추천 아이디어

1. **이력이 짧은 사용자의 텍스트 보조:** 사용자 평균 임베딩과 함께 실제 과거 리뷰별 matching, 행동 모델 fallback, 본문 수·관련 근거 수 feature를 비교한다. 식당에는 상대적으로 여러 근거가 있으므로 사용자/식당 encoder의 동일한 pooling이 적합한지 검토한다.
2. **평점과 속성 의견 분리:** 높은 별점 안의 불만·대조 표현과 낮은 평점의 구체 설명을 표본 주석한다. 별점만으로 긍정/부정 프로필을 나누는 방식과 속성별 근거 선택을 비교할 가설을 세운다.
3. **평균 대신 관련 근거 선택:** 짧은 리뷰별 검색 후 후보 식당과 관련된 속성·상황 근거만 재정렬에 전달한다. 리뷰 한 개의 긴 chunk 처리와 사용자 이력 전체의 근거 선택을 구분한다.
4. **과거 추가 리뷰의 활용:** cutoff 이전 전체 리뷰는 78,164건, 첫 상호작용은 70,883건이다. 제외되는 7,281건에 신규 정보가 있는지 확인한 뒤, 첫 방문 label을 유지하며 과거 추가 리뷰를 text sidecar에 쓰는 조건을 검토한다. 추가 기록을 실제 재방문이라고 자동 판정하지 않는다.

위는 데이터에 근거한 **미실행 가설**이다. 이번 프로파일로 RLMRec 개선의 원인이나 다른 모델의 성능 병목을 확정하지 않는다. 전체 DB 통계에는 holdout 시점 이후 리뷰도 포함되므로 새 모델 선택의 성능 증거로 사용하지 않는다.

## 앞선 로컬 수집 CSV 기초 조사

2026-10-10 실행. 대상은 `legacy/v1_rating_prediction/crawled_data/`의 CSV 5개이며 수집 파일 날짜는 2025-09-05~2026-03-22다. ingestion과 같은 정규화·필수 필드 검사·hash 구성 규칙으로 중복을 판정했다. 로컬 전용 salt를 쓰므로 hash 값 자체를 DB와 join할 수 있는 것은 아니다. DB 조회·API·재임베딩·학습은 수행하지 않았다.

CSV 파일명 정렬 순서에서 고유 content hash의 첫 대표행을 남긴다. 아래 본문·줄바꿈·날짜 통계는 이 대표행 기준이며 재수집된 모든 원본 행의 통계가 아니다.

| 노출·수집 편향·이력 불균형 | 지역·업종·수집 파일/시점별 분포, 리뷰 수 상위 사용자/식당 비중, 최소 이력 조건 전후 분포 | 특정 지역·고활동 사용자 결과를 전체 취향으로 확대하지 않는다. 층화 표본, 균등 집계, 평가 모집단을 정한다 |
| 날짜·신선도·변화 | 작성/수집 시각과 날짜 precision, 추정·대체 날짜 비율; 시간 구간별 평점/길이/주제/본문 결측 변화 | 추천 시점에 알 수 있던 정보를 재현한다. 오래된 경험과 최근 선호를 섞는 영향을 검토한다. 영업 상태 변화는 이 자료만으로 확정할 수 없다 |
| 엔티티 연결·재방문 | review→user/item join coverage, row 수 증감, 사용자/식당 식별 충돌, 같은 pair의 여러 리뷰와 첫 방문 선택 전후 차이 | 잘못 연결한 리뷰는 개인화 신호를 망친다. 원본 리뷰와 모델 interaction의 grain을 맞춘다 |
| 원문→모델 입력의 손실 | 원문/정규화/리뷰 선택/문장 분할/블록 제한/토큰 절단/집계 단계별 리뷰·문자·토큰·주석 속성 유지율 | 원문 정보 부족과 전처리 손실을 구분한다. 입력을 길게 하는 대신 관련 근거를 선택해야 하는지 판단한다 |
| label·시간 누수 | 타깃 방문 리뷰·평점·본문 별점 표현, 최신 aggregate, 미래 IDF/색인/임베딩의 cutoff 확인 | 모델이 추천 시점 이후의 답을 읽지 않게 한다. 본문 별점은 해당 리뷰 평점 추출 진단에서는 직접 단서이고, 과거 취향 입력에서는 사용 가능하다. 과제별로 구분한다 |
| 임베딩 표현의 성질 | 같은 모델·역할·cutoff에서 norm/cosine 분포, 사용자 간 유사도, 최근접 이웃의 주제·감정·중복, 평균 전후 의견 보존 | 인코더가 메뉴를 묶는지 취향을 구분하는지 확인한다. 군집이나 cosine 자체는 추천 성능의 증거가 아니다 |
| 사용자·식당 입력의 자기 리뷰 중첩 | 같은 리뷰가 사용자 프로필과 해당 식당 프로필 양쪽에 들어가는 비율·점수 민감도, 본인 리뷰 제외 조건 | 직접 텍스트 일치·문체 효과와 다른 식당에 대한 취향 일반화를 구분한다. 과거 공유 리뷰 자체를 미래 누수로 단정하지 않으며, 방문 식당의 추론 제외와 별도로 점검한다 |
| 검색 결과의 사용 가능성 | 요청/취향별 관련 근거, 부정 방향, 같은 식당의 반복 근거, hard negative, 기존 후보 밖 정답 유입과 기존 정답 탈락 | 리뷰 근거 검색과 식당 후보 검색의 실패를 분리한다. 검색 점수·근거별 matching을 ranker에 어떻게 전달할지 정한다 |

인코더 또는 임베딩 캐시를 조사할 때는 model revision·tokenizer·query/passage 역할·본문 hash·전처리 버전·cutoff를 함께 기록한다. 서로 다른 역할의 벡터를 무조건 같은 분포로 비교하지 않는다.

## 추천과 검색을 위해 특히 먼저 확인할 것

1. **실제 모델 입력 연결:** DB의 interaction snapshot·cutoff coverage를 확인했다. 다음에는 기존 review sidecar·E5 캐시의 본문 hash와 실제 선택 리뷰/블록을 연결한다. interaction digest 일치가 입력 본문의 동일성까지 보장하지 않는다.
2. **사용자별 정보량과 선택 편향:** 전체 본문 coverage와 함께 최소 이력 사용자·낮은 평점 리뷰의 본문 수를 확인한다. raw와 input에서 분모를 각각 기록한다.
3. **부정·대조·속성:** 학습 cutoff 이전 자료에서 평점·길이·지역·사용자 활동량별 층화 표본을 검토한다. 같은 사용자의 좋고 덜 좋았던 경험을 함께 본다. 현재 정규식 단서 비율은 감정 정답으로 쓰지 않는다.
4. **입력 손실:** 기존 원문과 모델별 실제 선택 리뷰·블록을 연결해 무엇이 버려졌는지 측정한다. 문자 보존률이 높아도 부정 대상·속성 의견을 보존했다는 뜻은 아니다.
5. **검색 실패 사례:** 관련 원문이 있었는지 → 후보로 검색됐는지 → 최종 후보에 남았는지 → 재정렬에서 올라갔는지를 분리한다. 저장 validation의 탐색 진단과 새 학습·일반화 검증을 구분한다.

의미 주석은 우선 100~200개 정도의 과거 리뷰를 층화 선택하는 미실행 제안이다. 소수 고활동 사용자의 긴 리뷰에만 집중하지 않는다. 같은 사용자·식당의 반복 사례 수를 제한하고, 표본 수·층별 추출확률·가중치·주석자·불일치 처리 방식을 기록한다. 과표집한 낮은 평점의 비율을 전체 감정 비율로 보고하지 않는다.

주석에는 구체 정보 있음/없음, 속성, 감정 방향, 부정 대상, 혼합 의견, 취향·이용 상황·의견 주체, 원문 구간, 불확실 여부를 남긴다. 외부 API 추출 품질과 원문 위치의 정확성은 별도로 확인한다. 이번에는 의미 주석·API 호출을 하지 않았다.

## 재현과 근거

프로젝트 루트에서 실행한다. Supabase 스크립트는 기존 `.env` 설정과 psycopg를 사용해 읽기 전용 조회한다. 연결 정보와 개인별 원문은 결과에 기록하지 않는다. CSV 스크립트는 DB에 연결하지 않는다.

```bash
.venv/bin/python scripts/profile_supabase_texts.py --train-cutoff 2025-12-19
```

- [Supabase 조회 SQL](../queries/profile_supabase_text.sql), [DB 프로파일 코드](../scripts/profile_supabase_texts.py).
- [독립 SQL 재검산](../artifacts/text_data/supabase_verification.json): 리뷰/본문/평점/고유 사용자–식당 수와 길이 분위수가 전체 조회 Python 집계와 일치.
- [DB 집계 JSON](../artifacts/text_data/supabase_profile.json): 조회 시각·읽기 전용 격리 수준·schema·실행 SQL·구현 SHA-256·cohort 정의·집계·한계.
- [DB 조사 노트북](../artifacts/text_data/supabase_profile.ipynb): 저장된 집계의 분모·해석·검증, SQL·코드 연결. DB를 자동 재조회하지 않는다. 코드 셀을 순서대로 실행해 출력 저장했고 Jupyter UI 렌더는 미확인이다. artifact는 Git에서 제외한다.

