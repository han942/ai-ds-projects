# RQ-VAE: 리뷰 임베딩을 이산 코드로 바꾼 효과

**연구 질문**

- 리뷰 임베딩의 이산 코드 압축률
- 원래 표현과 이웃 구조의 보존 정도
- 미래 식당 검색·순위에 미치는 영향

**현재 판단: 압축은 확인했지만 추천 모델은 유지한다.** 실행 기록상 Supabase 본문 리뷰 94,301개의 코드 생성과 validation 비교를 완료했다. 과거 리뷰의 코드+공유 모델 tensor payload는 원 벡터보다 **144.63배 작았지만**, 원래 Top-10 이웃 overlap은 **10.42%**였고 추천 개선은 확인하지 못했다.

1. 과거 리뷰 학습·평가

   - E5→RQ-VAE 압축·복원
   - Validation dense 검색과 C5 결합
   - 표현 보존과 추천 영향 비교

2. DB 전체 코드 적용

   - 과거에 학습한 모델을 이후 리뷰에도 고정 적용
   - 추가 RQ 학습 없음
   - DB 쓰기 없음
   - 미래 추천 검증이 아님

3. Generative Retrieval

   - 식당 ID 생성 모델 미구현
   - 리뷰 코드 생성과 식당 후보 ID 예측은 별도 작업

4. 현재 보관 상태

   - 코드·보고서 존재
   - 원 run 폴더는 로컬에 없음
   - 아래 수치는 실행 당시 기록
   - 이번 문서 정리에서 원 artifact 재검산 불가

## 코드화 대상

`리뷰 본문 → 고정 E5 임베딩 384차원 → 학습 encoder 32차원 → 잔차 양자화 3단계 → 코드 3개` 순서다. 예를 들어 `(17, 82, 4)`는 각 단계 코드북에서 선택한 벡터의 번호다. 코드 벡터를 합친 뒤 decoder를 통과하면 원래 384차원 공간의 근사 벡터를 복원할 수 있다.

각 단계는 이전 단계가 남긴 오차를 양자화한다. 숫자를 연속 실수처럼 평균하거나 코드 번호의 차이를 의미 거리로 쓰지 않는다. 첫 코드가 맛, 둘째가 가격 같은 해석을 자동으로 갖는 것도 아니다.

[TIGER](https://arxiv.org/abs/2305.05065)는 **식당/상품 같은 추천 대상**의 표현을 Semantic ID로 바꾸고, 별도의 생성 모델이 그 ID를 예측한다. 이번은 사용자가 지정한 **리뷰별 코드** 실험이다. 코드가 같은 리뷰를 하나로 삭제하지 않으며, 코드 자체는 고유 review ID나 식당 ID가 아니다. 식당 ID를 생성하는 추천 Transformer는 구현·학습하지 않았다.

RQ-VAE의 잔차 양자화·encoder/decoder·codebook/commitment loss는 [원 RQ-VAE 연구](https://arxiv.org/abs/2203.01941)와 [TIGER의 Semantic ID 학습](https://arxiv.org/html/2305.05065v3#S3.SS1)에 따른다. 모델 크기·입력·optimizer·학습 예산은 이 데이터에 맞춘 변경이다.

## 입력과 비교 조건

1. 과거 입력

   - 첫 사용자–식당 상호작용
   - `event_date ≤ 2025-12-19`
   - 모든 평점 유지

2. 리뷰 임베딩

   - `intfloat/multilingual-e5-small`
   - Revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`
   - 384차원 float32, L2 정규화

3. 역할·길이

   - 전체 리뷰에 `passage:` 사용
   - 리뷰별 최대 512토큰
   - RLMRec의 query/passage·문장 블록 캐시와 다른 입력 정책

4. 캐시

   - 기존 합성 프로필 캐시는 미사용
   - 리뷰별 로컬 E5 새로 생성
   - 외부 embedding API 호출 0회

5. 학습·검증 분리

   - 접두어와 512토큰 절단 후 E5 token IDs가 같은 리뷰를 한 그룹으로 처리
   - 과거 내부 fit 90%, audit 10%

6. 모델 구조

   - Encoder: 384→128→32
   - Decoder: 32→128→384
   - Codebook: 256개 × 3단계

7. Scaling

   - Fit 리뷰의 평균과 전역 RMS만 사용
   - 평균 벡터 복원 기준도 별도 비교

8. 최적화

   - AE warmup 5epoch
   - Fit latent 잔차 KMeans 초기화
   - RQ 학습 40epoch
   - Adam 0.001, batch 512, commitment β=0.25
   - seed 42, CPU 4threads

9. 모델 선택

   - 정해진 예산의 마지막 epoch 사용
   - 추천 validation 지표로 checkpoint·하이퍼파라미터를 선택하지 않음

10. 추천 평가

   - T1 이후부터 2026-05-04까지 validation
   - History-aware 만족도, min history 10
   - 평균 가중치 0.5, 이동 한도 0.5
   - Test 성능 미계산

11. 프로필·후보

   - 모든 평점의 최근 사용자 리뷰 최대 20개, 식당 최대 30개
   - 리뷰별 L2 정규화→동등 평균→프로필 L2 정규화
   - 과거 catalog와 K=100 고정
   - 방문 식당 제외
   - 사용자 본문이 없으면 인기 fallback

12. DB 전체 적용

   - 과거 fit 모델을 이후 리뷰에 업데이트 없이 적용
   - 미래 리뷰 코드는 앞선 validation 평가 입력에 미사용

역사적 event_date로 과거 경험을 재구성한 비교다. 리뷰가 실제 DB에 적재된 시점은 2026년 9월이므로, 당시 DB에서 이용 가능했던 텍스트라고 주장하지 않는다.

## 효과 분리 기준

1. 원래 E5와 코드 복원

   - 측정: MSE, 원래 벡터 cosine, 학습 평균 복원 대비 오차
   - 목적: 압축 후 표현 보존과 공통 성분 복원 착시 구분

2. 연속 경로와 코드 복원

   - 측정: 같은 encoder/decoder에서 양자화만 우회
   - 목적: 학습 경로와 이산 코드 경로의 출력 차이 확인
   - 한계: 독립 AE 실험이나 전체 양자화 인과 효과가 아님

3. 원래 이웃과 복원 이웃

   - 측정: 최대 1,000 query × 10,000 reference의 Top-10 overlap
   - 목적: E5 근접 구조 보존 확인
   - 한계: 전체 추천 Recall이나 실제 의미 정답과 다름

4. 코드 사용·충돌

   - 측정: 단계별 사용률, perplexity, 최대 버킷, prefix 중복
   - 목적: 코드 쏠림과 실제 분해능 확인
   - 같은 본문 반복도 충돌에 포함

5. 저장량

   - 비교: float32 벡터 vs 코드+공유 모델 tensor
   - ID·파일 포맷·원 벡터를 별도로 보존하는 연구용 디스크 비용은 제외

6. 추천 검색

   - 비교: raw / continuous / decoded 프로필
   - 지표: Recall@100, NDCG@10
   - 목적: 코드 복원의 미래 식당 검색 영향 확인

7. C5 결합

   - 비교: 같은 C5의 cosine 재정렬 또는 dense RRF 결합
   - 목적: 행동 후보 안 순위와 후보 보완 효과 구분

C5 비교는 **LambdaRank 이전 후보 순서**다. cosine 재정렬을 기존 학습된 LambdaRank의 개선으로 부르지 않는다. 동일 경로 raw와 RQ, C5와 각 경로의 NDCG@10 차이는 동일 사용자 paired bootstrap 2,000회로 계산한다. 이번 validation 결과는 탐색이며 독립 미래 holdout의 최종 증거가 아니다.

원래 E5와 코드 복원의 모든 경로는 C5 자체보다 NDCG@10이 낮았고, 각각의 paired 구간도 0보다 아래였다. C5 텍스트 재정렬의 Recall@100이 같은 것은 후보 집합을 유지하기 때문이다. RRF 결합은 K=100에서 행동 후보 일부를 대체하므로 후보 Recall이 낮아질 수 있다. 기존 **C5 + LambdaRank의 최종 지표**와 이번 C5 후보 순서를 혼동하지 않는다.

전체 고유 본문 93,449종의 접두어 포함 토큰 길이 P50/P90/P95/P99는 41/134/193/305.52이고 512토큰 초과는 102종 (0.11%)이다. 과거에 새로 만든 E5 입력 68,777종은 정확히 같은 본문 hash 정책으로 재사용하고 나머지 24,672종을 추가 인코딩했다. 전체 적용의 embedding 단계 423.39초는 재사용 경로를 포함하므로 처음부터 전체를 임베딩하는 시간은 아니다.

이 전체 적용 통계에는 미래 리뷰와 재방문도 있다. **추천 validation·표현 audit 결과는 위의 과거 입력에서 측정한 수치**이며, 미래 리뷰의 의미 보존이나 미래 추천 효과를 전체 적용 건수만으로 검증했다고 해석하지 않는다.

## 해석과 미실행 후속

확인한 문제는 **평균 cosine과 실제 이웃 보존의 차이**, 그리고 **텍스트 유사도만으로 행동 기반 후보 순서를 바꿀 때의 성능 손실**이다. 원래 E5 경로 자체도 C5보다 낮으므로 이번 추천 결과 전체를 이산화만의 문제로 설명할 수 없다.

원인 가설은 복원 MSE가 공통 문장 성분의 보존을 선호하고, 32차원 bottleneck·양자화·리뷰 평균이 선호에 중요한 차이를 충분히 보존하지 못한다는 것이다. 양자화를 우회해도 이웃 overlap이 낮은 점은 학습된 변환도 추가 조사할 근거다. 속성·긍정/부정 의미 손실을 주석으로 확인하거나 독립 AE를 학습하지 않았으므로 인과 원인으로 확정하지 않는다.

다음은 이번에 실행하지 않은 비교다.

1. 같은 코드 예산에서 원래 이웃 또는 추천 선호 거리를 보존하는 contrastive loss를 추가한다.
2. latent 차원 또는 단계·코드 수를 한 요인씩 바꾸고 표현 손실과 validation을 함께 비교한다.
3. C5 행동 점수를 유지한 리뷰 코드 보조 feature는 과거 미실행 설계로 보존한다. 현재 retrieval 전용 후속에서는 재정렬을 보류한다.
4. 리뷰 코드의 시간 순서를 사용자 sequence encoder에 넣는 설계를 검토한다. 식당 ID 생성 모델은 별도 실험이다.
